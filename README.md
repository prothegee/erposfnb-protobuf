# erposfnb-protobuf

Single source of truth for every `.proto` file in the project and its generated Go code.

This directory is its own Go module: `github.com/prothegee/erposfnb-protobuf`.

## Generate

Run the generator from this directory.

```sh
sh gen.sh
```

`gen.sh` calls plain `protoc` with the Go and Go gRPC plugins. It writes each `*.pb.go` next to its `.proto` source. No `buf` config is used anywhere.

Generated files are committed. A drift check reruns `gen.sh` and diffs the tree.

## Test

`enum_contract_test.go` walks the enums of every package and checks three rules: tag 0 ends in `_UNSPECIFIED`, each value name starts with its enum name, and tags climb in declaration order.

```sh
go test ./...
```

## Enum Rules

| Rule | Detail |
| :- | :- |
| Zero value | Tag 0 is `<ENUM>_UNSPECIFIED` and never carries a real value. |
| Value name | `UPPER_SNAKE`, prefixed with the enum name, for example `ORDER_STATUS_PENDING`. |
| Tag numbers | Append only. A tag number is never reused. |
| Removal | Removing a value is a breaking change and needs a major version bump. |
| Ownership | `common.proto` holds an enum used by two or more service contracts. A service local enum lives in that service `.proto`. |
| DB mapping | Each service maps a proto value to its own DB enum with one mapper file per enum pair. |

The suffix of a proto value maps to the DB enum value by name after the prefix is stripped and the text is lowercased. For example `ORDER_STATUS_DINE_IN` maps to `dine_in`.

## Consume

A service in development replaces the module in its `go.mod`.

```
replace github.com/prothegee/erposfnb-protobuf => ../erposfnb-protobuf
```

A staging or production service pins a tagged version instead.
